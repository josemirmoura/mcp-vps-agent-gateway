# Runtime semantics and recovery

This document defines operational behavior that must be explicit before production.

## 1. Lease expiry during long-running jobs

A privileged job derives an immutable **job grant** from the lease at job start.

Default rule:

```text
job_deadline <= lease_expiry
```

The Broker must configure the execution deadline accordingly. When the grant expires:

1. stop accepting privileged mutations from that job
2. send graceful termination to the managed process/cgroup
3. after a bounded grace period, force termination
4. persist the final state and audit event

Routine Scoped jobs do not need a Full lease.

If a specific administrative job must outlive the interactive lease, the human must explicitly approve an action-specific completion grant with its own bounded deadline. This is exceptional, visible and auditable.

## 2. SQLite concurrency

SQLite is intentionally single-writer. This is acceptable if the Broker uses it correctly.

Rules:

- only the Broker opens the database
- transactions are short
- **never keep a SQLite transaction open while a shell command, deploy, migration or Docker operation runs**
- persist a state transition, commit, perform the external work, then persist the next state
- long-lived mutual exclusion uses logical resource locks with leases/deadlines, not a long DB transaction
- WAL mode is enabled
- use busy timeout/backoff for short write contention

If measured contention becomes material, migrate the state store. Do not preemptively add a distributed database.

## 3. Idempotency keys are infrastructure metadata

Do not depend on the LLM to invent a stable idempotency key.

Preferred behavior:

- idempotency metadata is generated by the client adapter/Gateway, not exposed as a semantic choice to the model
- bind the key to authenticated subject, canonical tool name and normalized request hash
- if the transport/client provides a stable invocation/request identity, incorporate it
- if no stable retry identity exists, state-changing operations are not automatically retried

Identical tool arguments alone are insufficient to infer a retry because the user may legitimately request the same action twice.

## 4. Secret management

The MVP should avoid secret-reading tools entirely.

For a single Linux VPS, the default production mechanism should prefer native service-secret delivery:

- root-owned files outside the repository with strict permissions, and/or
- systemd credentials (`LoadCredential=` / credential directory) for Gateway/Broker service secrets

The Broker resolves a `secret_ref` internally and injects the value only into the target process.

Optional external providers such as Vault/cloud secret managers can be added behind a provider interface when there is a concrete need.

Rules:

- Gateway cannot read plaintext secret storage
- model-facing tools cannot enumerate secret values
- secrets are never stored in SQLite audit payloads
- secret values are redacted from stdout/stderr and logs where practical

## 5. Approval friction

Full elevation is not the normal operating mode.

Routine unattended or overnight work must run under a pre-authorized **Scoped** policy with explicit resources and bounded actions.

Out-of-band approval is reserved for exceptional privilege escalation.

This avoids turning normal operations into a stream of phone approvals while preserving a strong boundary for administrative access.

## 6. Recovery of the gateway itself

### Broker hangs during a job

- each job runs in its own managed systemd unit/cgroup
- execution has a deadline
- Broker restart must reconcile persisted job state against existing units/processes
- orphan jobs are either adopted for monitoring or terminated according to policy

### SQLite corruption

Fail closed:

1. stop Gateway/Broker writes
2. invalidate pending approvals
3. treat all Full/elevated leases as revoked
4. preserve the damaged DB for forensic analysis
5. restore the latest verified backup
6. reconcile active systemd job units
7. re-enable service only after integrity checks

### Erroneously issued lease

Provide an emergency operation outside the AI tool surface:

```text
vps-agent revoke-all
```

It must:

- revoke all elevated leases
- prevent new elevated starts
- terminate or quarantine active jobs derived from revoked grants according to emergency policy
- emit an audit checkpoint

If credential compromise is suspected, rotate the affected OAuth/client/secrets separately.

### Gateway route compromise

Stopping or removing the MCP route must not stop existing application workloads.

## 7. Backups

At minimum back up:

- policy configuration
- SQLite state
- audit checkpoints
- deployment unit files

Backups must not contain plaintext secrets unless encrypted and intentionally included.

## 8. Production readiness gates

Before broad production access:

- Gate 0 client compatibility passed
- Gate 1 privileged typed action passed
- Scoped has been used successfully on a real stack
- lease/job deadline semantics tested
- SQLite recovery tested
- revoke-all tested
- secret provider path tested
- gateway removal leaves workloads running
