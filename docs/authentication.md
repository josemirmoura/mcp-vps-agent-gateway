# Authentication

Checked against the current MCP/OpenAI OAuth model on 2026-09-27.

## Supported product path

The supported public ChatGPT path is **integrated self-hosted OAuth/OIDC**.

The package runs a dedicated ZITADEL instance plus PostgreSQL beside the Gateway. The supported path is self-contained and does not require a third-party identity service or separate tunnel.

Local/lab verification still uses the static bearer token generated by `scripts/init.sh`. That token never becomes the public ChatGPT credential.

## Public topology

~~~text
ChatGPT
   |
   | HTTPS + OAuth 2.x / OIDC
   v
public domain
   |-------------------------------|
   |                               |
   v                               v
Gateway                         ZITADEL
protected resource             authorization server
   |                               |
   v                               v
Broker                       PostgreSQL identity state
   |
   v
VPS
~~~

The same public hostname can serve both roles. Router priority sends `/mcp`, `/healthz` and RFC 9728 protected-resource metadata to the Gateway; OAuth/OIDC discovery, login, token, user-info and DCR endpoints go to ZITADEL.

## Bootstrap

Run:

~~~bash
bash scripts/setup-integrated-auth.sh
~~~

The script generates the identity-stack secrets, reuses an existing Traefik when possible, starts the bundled edge only on a clean host, starts ZITADEL/PostgreSQL, enables open Dynamic Client Registration required by MCP clients, creates a dedicated non-admin operator identity, records its stable subject in `.env`, then recreates Gateway/Broker in integrated mode.

The operator password is read without terminal echo. It is never written to `.env` or the state marker.

The temporary bootstrap human IAM owner is deleted after the dedicated operator is created. The bootstrap machine PAT is then removed from the bootstrap volume. The internal login-client PAT remains in the private Docker volume because ZITADEL Login requires it.

## MCP protected-resource metadata

The Gateway exposes:

~~~text
/.well-known/oauth-protected-resource
~~~

For integrated mode it normally advertises:

~~~text
resource: https://mcp.example.com/mcp
authorization_servers:
  - https://mcp.example.com
scopes_supported:
  - openid
bearer_methods_supported:
  - header
~~~

`scripts/verify-public.sh` verifies that metadata, OIDC discovery, DCR advertisement, S256 PKCE support, HTTPS and unauthenticated MCP denial.

## Why integrated token verification is different

ZITADEL's MCP-oriented Dynamic Client Registration currently creates public OAuth clients that receive opaque bearer access tokens. Its DCR implementation accepts the RFC 8707 `resource` parameter but does not narrow the access-token audience to that resource.

For that reason the integrated Gateway does **not** disable validation globally and does not add a generic "skip audience" switch.

Instead, integrated mode validates each bearer token online against the dedicated ZITADEL issuer's UserInfo endpoint. The resulting stable `sub` becomes the MCP subject. The Broker independently checks that subject against `VPS_AGENT_SUBJECT` before any non-admin operation.

This model is intentionally scoped to the dedicated identity instance installed for this MCP. It should not be reused as a generic verifier for unrelated OAuth issuers.

## Dynamic Client Registration

MCP clients register before an operator has authenticated, so ZITADEL DCR is enabled with unauthenticated registration. The dedicated DCR endpoint is rate-limited at the Traefik layer. Dynamically registered clients live in ZITADEL's dedicated DCR project.

The operator still has to authenticate before ChatGPT receives a usable access token.

## Subject binding

The setup script creates a dedicated regular human user for the VPS operator and writes that user's chosen stable ID to:

~~~dotenv
VPS_AGENT_SUBJECT=<operator-user-id>
~~~

The bootstrap IAM owner exists only during first-instance setup and is removed before installation proceeds. It is never the identity accepted by the Broker.

## Fail-closed rules

- The local Gateway starts on loopback/static auth for deterministic local acceptance.
- A public MCP URL is rejected unless the Gateway runs in integrated mode.
- `verify-public.sh` rejects non-HTTPS public URLs.
- public metadata must identify the expected resource and issuer.
- integrated OIDC discovery must advertise DCR and S256 PKCE.
- unauthenticated `/mcp` must return HTTP 401.
- the Broker rechecks the exact expected subject and policy after Gateway authentication.
- the Gateway still has no host root and no Docker socket.

## Edge proxy

If exactly one running Traefik is detected, the installer joins its Docker network and reuses its ACME resolver. If no Traefik is present and host ports 80/443 are free, the package starts its own pinned Traefik.

The automatic installer refuses to replace an unknown web server already occupying 80/443.

## Local/lab static bearer

Static bearer remains only for local CI and pre-public verification:

~~~dotenv
VPS_AGENT_AUTH_MODE=static
~~~

It is intentionally not the public ChatGPT path.
