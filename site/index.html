MCP VPS Agent Gateway
GitHub PT-BR

Docker-first · policy-enforced · auditable

Give ChatGPT real VPS capabilities without handing the model an unrestricted root shell.

A remote MCP Gateway authenticates the client. A privileged local Broker re-authorizes every host operation against the scope chosen by the VPS owner.

Quick StartRead the docs

Operator-defined authority

Delegate one project, several roots, selected services and containers, or broader host authority. Filesystem, shell, systemd, Docker, network and admin capabilities remain separate policy decisions.

Privilege stays server-side

The Gateway is non-root and receives neither /host nor the Docker socket. The Broker is local-only, privileged and policy-authoritative.

Proof before success

Healthy containers are only a checkpoint. Installation completes after a real ChatGPT MCP call crosses authentication, policy, Broker execution and the tamper-evident audit trail.

Security

The LLM is not the authorization engine.

Deny-by-default policy, scoped filesystem resolution, isolated shell/jobs, bounded requests, expected-subject checks, operation journals, locks/fencing and a Broker-owned audit hash chain keep authority in code the operator controls.

Identity

OAuth without an OAuth homework assignment.

The supported public path self-hosts ZITADEL beside the Gateway. The setup script creates the operator identity, a dedicated MCP audience, private token introspection, dynamic client registration and reuses the VPS edge proxy when possible.

Quick Start

Clone, choose scope, start, verify.

git clone https://github.com/josemirmoura/mcp-vps-agent-gateway.git &&
cd mcp-vps-agent-gateway &&
sudo install -d -o "$USER" -g "$(id -gn)" -m 0750 /opt/vps-agent-sandbox &&
bash scripts/init.sh --scope /opt/vps-agent-sandbox &&
docker compose up -d --build &&
bash scripts/verify.sh

The Quick Start delegates only /opt/vps-agent-sandbox. Change that path to the existing directory you want the MCP to control. The && chain stops at the first failed step instead of continuing into a broken verification.

Local verification is only checkpoint one. To finish, point a DNS hostname at the VPS and run the integrated-auth step below. No third-party identity provider account is required.

Step 2 · Connect ChatGPT

One domain, integrated OAuth, real proof.

Create a DNS A/AAAA record such as mcp.example.com pointing to the VPS. Then run the block below; the setup asks for the domain, operator email and password interactively:

bash scripts/setup-integrated-auth.sh &&
bash scripts/connect-chatgpt.sh

The setup script asks locally for the dedicated OAuth operator email and password, then handles the rest: existing Traefik detection or bundled edge on a clean VPS, TLS, ZITADEL + PostgreSQL, dedicated operator identity, MCP-only resource audience, private token introspection, DCR, PKCE discovery, Gateway/Broker identity binding and public verification.

No VPS or SSH credentials are given to ChatGPT. The supported installation never requires a VPS password, private SSH key or unrestricted remote admin access to be shared with ChatGPT or a maintainer.

connect-chatgpt.sh does not declare victory when it merely prints instructions. It waits until ChatGPT actually calls system.info and the Broker audit confirms the authenticated request.
